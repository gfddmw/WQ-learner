# Android 前端全面优化设计

日期：2026-05-12

## 目标

本轮优化把 WQ Learner Android 端从“功能验证界面”推进到“可长期使用的真实 App 界面”。视觉方向采用混合方案：上传页借鉴“学习工作台”的安静、低干扰风格；题库页、练习页和我的页采用“任务流卡片”的推进感，让每个按钮都对应明确的云端或本地状态动作。

本设计只覆盖 Android 前端体验和按钮行为，不改变已经接入的函数计算、OSS、表格存储、OCR、变形题生成等后端能力。

## 视觉方向

整体基调为浅色、克制、学习工具感。页面背景使用柔和浅灰或暖白，主要按钮使用沉稳蓝色，状态标签使用绿色、橙色、红色表达成功、等待和错误。避免大面积单一紫色、营销式英雄区和过度装饰。

上传页更安静：图片预览、识别草稿、分类确认按自然顺序排列，降低拍照后的认知压力。

题库页和练习页更任务化：每道题作为一个可推进任务卡，清楚展示科目、章节、掌握状态和可执行动作。

## 信息架构

底部仍保留四个主入口：

1. 上传：拍照或相册导入错题，自动上传云端识别，用户校正后确认入库。
2. 题库：从云端刷新错题，按科目和掌握状态筛选，查看题目卡片。
3. 练习：抽现有错题、生成变形题、更新掌握状态。
4. 我的：账号登录、注册、退出、云端连接状态和服务状态。

导航标签使用清晰中文，不再显示单字占位。当前页需要有明显选中态。

## 页面设计

### 上传页

上传页采用“学习工作台”布局，重点是顺序和确定性。

核心区域：
- 图片草稿卡：显示图片预览、拍照识别、相册导入、清除。
- 识别校正卡：显示 Markdown + LaTeX 题干输入框、科目输入、章节输入。
- 入库操作区：确认入库、上传中禁用、成功后给出题目 ID 和下一步入口。

按钮行为：
- 拍照识别：打开系统相机，拍照成功后立即上传识别。
- 相册导入：打开系统相册，选图成功后立即上传识别。
- 清除：清空图片、识别草稿和状态提示。
- 确认入库：保存当前校正后的题干、科目、章节和掌握状态；如果后端暂不支持独立更新草稿，则先保持为本地题库同步动作，并在后续后端接口补齐时接入真实更新。

### 题库页

题库页采用任务流卡片。顶部提供科目筛选和刷新动作，列表展示云端错题。

核心区域：
- 筛选条：全部、数据结构、计算机组成原理、操作系统、计算机网络、数学。
- 状态筛选：全部、仍不熟、复习中、已掌握。
- 题目卡片：科目/章节、题干摘要、掌握状态、更新时间或来源。

按钮行为：
- 从云端刷新题库：调用云端 `/questions`，同步到当前列表。
- 科目筛选：只改变当前筛选并可触发刷新。
- 状态筛选：本地筛选已加载题库。
- 题目卡片：展开详情，展示完整题干和后续操作入口。

### 练习页

练习页强调推进。优先从未掌握或复习中的题目抽取；变形题基于当前题生成。

核心区域：
- 模式切换：抽现有错题、生成变形题。
- 当前训练卡：显示原题或变形题内容、答案、解析。
- 反馈按钮：仍不熟、复习中、已掌握。

按钮行为：
- 抽现有错题：从当前题库按掌握状态优先级抽取一题，并避免总是取第一题。
- 生成变形题：对当前题调用云端 `/practice/variant`；没有当前题时提示先刷新或上传题库。
- 仍不熟 / 复习中 / 已掌握：更新当前题掌握状态，后端接口可用时写回云端；同时更新本地列表，避免按钮空点。

### 我的页

我的页去掉开发痕迹，只保留真实 App 需要的信息。

核心区域：
- 账号卡：邮箱、密码、登录、注册并登录、退出。
- 云端状态卡：当前 API 地址、登录状态、FC/OSS/表格存储/OCR/变形题服务状态。
- 设置卡：必要时允许查看当前云端 API，但默认不要求普通用户修改。

按钮行为：
- 登录：调用云端登录，保存 token。
- 注册并登录：先注册，再登录并保存 token。
- 退出：清除 token 和本地会话。
- 检查云端状态：调用 `/health`；如果后端补充服务状态接口，则显示 OSS、表格存储、模型配置状态。

## 组件边界

现有 `MainActivity.kt` 已经偏大。本轮开发应在不大拆工程的前提下提取前端组件，优先拆出：

- 通用布局：`ScreenScaffold`、`SectionHeader`、`TaskCard`、`StatusPill`、`PrimaryActionRow`。
- 业务组件：上传图片卡、识别校正卡、题库筛选条、题目任务卡、练习反馈按钮、云端状态卡。
- 状态辅助：抽题选择逻辑、掌握状态更新逻辑、上传流程状态。

这样可以让页面代码更清楚，也方便后续单元测试。

## 数据流

上传流程：
图片来源 -> 图片预览 -> 云端上传识别 -> 返回草稿 -> 用户校正 -> 确认入库 -> 更新本地题库列表。

题库流程：
登录 token -> 云端 `/questions` -> 本地列表 -> 科目/状态筛选 -> 题目卡展示。

练习流程：
本地题库列表 -> 抽题或选择当前题 -> 生成变形题或原题练习 -> 掌握状态按钮 -> 更新本地状态并尽量写回云端。

账号流程：
登录/注册 -> token 持久化 -> 各页面共享登录状态 -> 退出清除 token。

## 错误处理

所有按钮都要有可见状态反馈：
- 未登录：提示去“我的”页登录。
- 上传中或生成中：禁用重复点击。
- 网络失败：显示云端错误摘要，不展示长堆栈。
- 空题库：给出刷新题库或上传错题的明确下一步。
- 识别失败：保留图片，允许重试或手动录入。

## 测试

优先补充可单测的状态逻辑：
- 抽题不总是返回第一题，并优先未掌握题。
- 掌握状态按钮能更新题目状态。
- 上传状态能防止重复提交。
- 登录状态恢复后各页面能识别已登录。
- API 地址保持云端默认，不回退到本地后端。

视觉验收以真机截图为准：底部导航文字完整、按钮不挤压、长题干不遮挡底部导航、任务卡在窄屏可读。

## 验收标准

- 四个底部页面视觉统一，上传页更安静，题库和练习页有任务流推进感。
- 所有当前可见按钮都有明确行为，不再有空 `onClick`。
- 上传后自动识别题干，用户能校正并确认进入题库。
- 题库可刷新、筛选、查看题目详情。
- 练习页可抽题、生成变形题、更新掌握状态。
- 我的页保留真实云端 App 逻辑，隐藏不必要的本地开发表达。
- Android 单元测试通过；如本机 Java 环境不足，需要记录限制并在可用 JDK 17 环境下补跑构建。
