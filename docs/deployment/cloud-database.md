# 云端数据库适配说明

WQ Learner 后端已经把业务层使用的数据访问能力抽象为 `Store` 协议。当前代码仍默认使用 SQLite，方便本地开发和自动化测试；函数计算正式运行时不应依赖本地 SQLite 作为长期数据源。

## 当前实现

后端数据层入口在：

```text
backend/app/store.py
```

当前包含：

- `Store`：业务层依赖的数据访问协议。
- `SQLiteStore`：本地开发和测试使用的 SQLite 实现。
- `CloudDatabaseStore`：云端数据库占位实现，后续接入真实数据库。
- `create_store()`：根据环境变量创建具体 Store。

`main.py` 只使用模块导出的 `store`，不直接依赖 SQLite 细节。这样后续把数据源切到 RDS、表格存储或其他云端数据库时，API 层不需要大改。

## 环境变量

| 名称 | 当前用途 | 说明 |
| --- | --- | --- |
| `WQ_LEARNER_DB` | SQLite 数据库路径 | 仅用于本地开发、测试或临时验证 |
| `WQ_LEARNER_DATABASE_URL` | 云端数据库连接地址 | 设置后会进入云端数据库适配入口 |

当前 `WQ_LEARNER_DATABASE_URL` 只用于验证配置入口，真实云数据库实现会在后续功能中补齐。如果现在设置该变量，接口会返回“云端数据库适配层已预留”的未实现错误。

## 推荐迁移路线

第一阶段保留 SQLite：

- 本地开发继续使用 `WQ_LEARNER_DB`。
- 自动化测试继续使用临时 SQLite 文件。
- 函数计算只做健康检查、登录链路验证和后续适配准备。

第二阶段接入云端数据库：

- 优先选择一个简单可维护的数据源。
- 小规模阶段可使用阿里云 RDS MySQL/PostgreSQL。
- 如果更偏 Serverless，可评估表格存储或其他托管数据库。
- 新实现应实现 `Store` 协议中的全部方法。

第三阶段迁移数据：

- 从 SQLite 导出用户、token、错题、练习记录。
- 写入新的云端数据库。
- 函数计算环境设置 `WQ_LEARNER_DATABASE_URL`。
- 验证注册、登录、上传、题库和练习接口。

## 函数计算注意事项

- 不要把函数计算本地磁盘当成正式数据库。
- 函数实例可能冷启动、扩缩容或重建，本地文件不适合保存用户数据。
- 数据库账号、密码、连接串应通过函数计算环境变量或密钥管理配置。
- 后续生产环境要补充连接池、超时、重试和最小权限账号。
